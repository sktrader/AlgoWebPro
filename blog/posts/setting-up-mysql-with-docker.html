Setting up MySQL with Docker

Sep 5, 2026 · 7 min read

This picks up right after installing Docker. Instead of installing MySQL directly on your machine, you'll run it in a container — which means no messy uninstall later, and you can run different MySQL versions side by side for different projects.

The one-line version

This gets MySQL running immediately, but skips persistence — read the next section before you use this for anything real:

docker run --name mysql-dev -e MYSQL_ROOT_PASSWORD=devpassword -p 3306:3306 -d mysql:8.0

Breaking that down: --name mysql-dev names the container so you can refer to it later, -e MYSQL_ROOT_PASSWORD sets the root password, -p 3306:3306 maps the container's MySQL port to your machine's port 3306, and -d runs it in the background.

Do this instead: add a persistent volume

Without a volume, all your data disappears the moment you remove the container. A Docker volume stores the actual database files outside the container, so they survive restarts, rebuilds, and version upgrades:

docker volume create mysql-data

docker run --name mysql-dev \
  -e MYSQL_ROOT_PASSWORD=devpassword \
  -v mysql-data:/var/lib/mysql \
  -p 3306:3306 \
  -d mysql:8.0

Now the database files live inside the mysql-data volume, not inside the container itself.

The mistake that loses data: running docker rm mysql-dev is safe — your data in the volume survives. Running docker volume rm mysql-data is not — that deletes the actual database. Only remove the volume when you genuinely want a clean slate.

Using docker-compose instead

For anything beyond a quick test, a compose file is easier to re-run and version-control than remembering a long docker run command. Create a file named docker-compose.yml:

services:
  mysql:
    image: mysql:8.0
    container_name: mysql-dev
    environment:
      MYSQL_ROOT_PASSWORD: devpassword
      MYSQL_DATABASE: myapp
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql

volumes:
  mysql-data:

Then start it from the same folder:

docker compose up -d

The MYSQL_DATABASE line above also creates an empty database called myapp automatically on first startup — one less manual step.

Connecting to it

Check the container is actually up and healthy:

docker ps

Then connect using the MySQL client from inside the container itself — no local MySQL install needed:

docker exec -it mysql-dev mysql -uroot -p

Enter the password you set above. To connect from an external tool instead — MySQL Workbench, DBeaver, or your Spring Boot app — use localhost, port 3306, username root, and the same password.

Common issues

  • "Connection refused" right after starting: MySQL takes a few seconds to initialize on first run. Check progress with docker logs mysql-dev and wait for a line saying it's ready for connections.
  • "Port already in use": something else on your machine is already using port 3306 — likely a local MySQL install. Either stop that service or map to a different host port, e.g. -p 3307:3306.
  • Changed the password but it didn't take effect: environment variables like MYSQL_ROOT_PASSWORD only apply the very first time a fresh volume is initialized. If you need to change it later, do it through SQL (ALTER USER) rather than restarting with a new env var.
