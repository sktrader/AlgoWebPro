Installing Docker: a clean setup on Windows, Mac, and Linux

Aug 29, 2026 · 6 min read

Every Docker tutorial assumes Docker is already installed and working. It rarely just works on the first try, so this post is the setup step everyone skips — done properly, once, so every tutorial after this one starts from a clean state.

What you're actually installing

On Windows and Mac, you install Docker Desktop — a GUI app that runs a lightweight Linux VM in the background and gives you the docker command in your terminal. On Linux, you install Docker Engine directly — no VM needed, since Docker is Linux-native.

Windows setup

Docker Desktop on Windows needs WSL2 (Windows Subsystem for Linux) as its backend. Most modern Windows 10/11 installs already have it, but if this is a fresh machine, enable it first:

wsl --install

Restart if prompted. Then download Docker Desktop from docker.com, run the installer, and make sure "Use WSL 2 instead of Hyper-V" is checked during setup. Launch Docker Desktop once after install and wait for the whale icon in your system tray to stop animating — that means the engine is ready.

Common snag: if the installer complains that virtualization is disabled, you'll need to enable it in your BIOS/UEFI settings (usually called "Intel VT-x" or "AMD-V") and reboot.

Mac setup

Download Docker Desktop for Mac from the same docker.com page — pick the Apple Silicon build if you're on an M-series chip, or the Intel build otherwise. Drag it into Applications, launch it, and grant the permissions it asks for. No extra configuration needed.

Linux setup (Ubuntu/Debian example)

On Linux you install Docker Engine directly, no desktop app required:

sudo apt-get update
sudo apt-get install ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

By default, Docker commands need sudo on Linux. To run Docker as your normal user, add yourself to the docker group, then log out and back in:

sudo usermod -aG docker $USER

Verify the install

Once installed — on any OS — open a terminal and check the version:

docker --version
docker compose version

Then run the classic sanity check. This pulls a tiny test image and confirms Docker can actually create and run a container end to end:

docker run hello-world

If you see a message starting with "Hello from Docker!", the install is good and you're ready for the next tutorial.

Linux permission denied error? That almost always means the group change from the step above hasn't taken effect yet — fully log out and back in (or reboot), then try again.
